## Overview

### 누가, 어떻게 쓰나

GA4 보고서 개요(2026-10-09 ~ 2026-11-05) 기준입니다. 측정 설계는 [analytics-events.md](../docs/analytics-events.md)에 있습니다.

| 사실 | 값 | 설계에 주는 의미 |
| --- | --- | --- |
| 기기 | 모바일 84.6%, 데스크톱 14.6% | 360px 화면이 기준입니다. 데스크톱은 넓혀서 보여 주는 화면입니다 |
| 첫 유입 | 활성 사용자 741명 중 556명이 `m.search.naver.com` | 대부분 홈이 아니라 **상세·주제 페이지로 바로 들어옵니다**. 상세가 실제 첫 화면입니다 |
| 평균 참여 시간 | 37초 | 언제·어디서·얼마·신청 방법을 첫 화면에서 답해야 합니다 |
| 지역 | 서울 291, 속초 170, 부산 84 | 외지 방문객과 주민이 섞여 있습니다. "내가 가는 날 뭐 하지?"(날짜)로 찾습니다 |
| 재방문 | DAU/MAU 1.5% | 한 번 보고 떠납니다. 재방문 장치(알림)는 별도 과제입니다 |

### 원칙

1. **결정 정보 먼저.** 상세 페이지는 360×740 화면 안에 제목, 날짜, 장소, 신청·안내 버튼이 보여야 합니다.
2. **포스터가 보이게, 훑어보기 쉽게.** 행사 포스터는 정보의 큰 부분이라 목록에서도 크게 보여 줍니다(2열 카드). 날짜·장소는 항상 같은 자리에 둡니다.
   처음에는 작은 썸네일 목록 행을 썼지만, 64~80px로는 세로 포스터를 알아볼 수 없어 바꿨습니다(2026-11-06).
   모바일에서도 글을 처음부터 읽는 이해도는 데스크톱과 비슷하지만, 탐색·비교 작업은 모바일이 더 불리합니다
   ([NN/g, Reading Content on Mobile Devices, 2016](https://www.nngroup.com/articles/mobile-content/)).
3. **절제.** 색은 바다색 하나와 상태색만 씁니다. 굵기는 네 단계, 장식은 쓰지 않습니다. 강조는 크기·굵기·위치로 만듭니다.
4. **신뢰.** 공공 정보를 옮기는 서비스입니다. 출처와 "원문 확인" 안내가 늘 보여야 하고, 과장된 표현과 장식을 피합니다.
5. **모바일 우선, 앱으로 옮길 수 있게.** 웹에만 있는 상호작용(hover로만 보이는 정보 등)에 기대지 않습니다.

## Colors

### 원본 팔레트(primitive)

`sea`(속초 바다색)와 `gray`(바다색 쪽으로 아주 약하게 기운 회색) 두 가지입니다. 값은 `app/globals.css`에 있습니다.
컴포넌트에서 직접 쓰지 않고, 아래 역할 토큰을 거쳐서만 씁니다.

### 역할 토큰(semantic)

Tailwind v4의 `--color-*`로 정의되어 `bg-surface`, `text-content-muted`처럼 씁니다.

| 토큰 | 원본 | 쓰는 곳 |
| --- | --- | --- |
| `surface` | 흰색 | 페이지·카드 배경 |
| `surface-subtle` | `gray-50` | 구역 배경 |
| `surface-muted` | `gray-100` | 이미지 없는 포스터 자리, 비활성 배경 |
| `skeleton` | `gray-200` | 로딩 자리 |
| `content-strong` | `gray-900` | 제목, 선택된 칩 배경 |
| `content` | `gray-800` | 본문(전역 기본 글자색) |
| `content-muted` | `gray-600` | 보조 문장 |
| `content-subtle` | `gray-500` | 날짜·장소 같은 메타, 출처 |
| `content-placeholder` | `gray-500` | 입력창 placeholder |
| `line` | `gray-200` | 구분선, 포스터 테두리 |
| `line-strong` | `gray-300` | 칩·보조 버튼 테두리 |
| `line-input` | `gray-400` | 입력창 테두리(배경 대비 3:1 이상) |

| `primary-hover` | `sea-700` | 주요 버튼 hover·pressed |

| `primary-subtle-hover` | `sea-100` | `tonal` 버튼 hover·pressed |
| `primary-text` | `sea-700` | 링크, `primary-subtle` 위의 글자 |
| `accent` / `accent-hover` | `gray-800` / `gray-900` | primary 옆의 두 번째 채운 버튼(상세 `신청·예매`) / hover·pressed. 파랑과 계열이 다른 진한 차콜, 흰 글자 대비 약 13:1. 중간 회색(`gray-600`)은 누를 수 없는 버튼처럼 보여 쓰지 않음 |

명도 대비(WCAG 2.x 계산식, 2026-11-06 계산): `content-subtle`/흰색 5.35, `content-subtle`/`surface-subtle` 5.02,
`primary`/흰색 6.05, `primary-text`/`primary-subtle` 7.16, `danger`/`danger-subtle` 5.75, `success`/`success-subtle` 5.71,
`line-input`/흰색 3.09. 글자는 4.5 이상, 입력창 테두리·아이콘 같은 UI 요소는 3 이상을 지킵니다.

### 행사 상태의 색

한 항목에 배지는 **최대 2개**입니다. 아래 우선순위로 고르고, 나머지는 메타 줄에 글자로 씁니다.

| 우선순위 | 상태 | 표현 |
| --- | --- | --- |
| 1 | 오늘 마감, 신청 D-1~D-3(KST 달력 날짜 기준) | `danger-subtle` 배지 + `danger` 글자 |
| 2 | 사전 신청(신청이 필요하고 마감까지 4일 이상 남았거나 마감일이 없음) | `success-subtle` 배지 + `success` 글자. "신청 가능"은 '신청해도 된다'로도 읽혀 쓰지 않습니다(2026-11-06) |
| 3 | 무료 | `line-strong` 테두리 배지 + `content-muted` 글자 |
| - | 진행 중, 예정 | 배지 없이 메타 줄의 날짜 앞에 글자로("진행 중 · 11.1 – 11.21") |
| - | 새로 올라옴 | 사이트에 공개된 지 7일이 지나지 않은 행사(`isRecentlyPublished`, 기준은 `published_at`). 포스터 오른쪽 위의 `NEW`(`primary` 바탕, 흰 글자). 상태 배지(최대 2개)와 따로 둡니다. 동그란 "N"은 촌스러워 보여 바꿨습니다(2026-11-06). 마감·종료된 행사에는 붙이지 않습니다 |
| - | 마감, 종료 | `surface-muted` 배지 + `content-subtle` 글자. 투명도(opacity)로 흐리게 하지 않습니다 |

## Typography

### 글꼴

- **Pretendard Std Variable**([SIL OFL 1.1](https://github.com/orioncactus/pretendard), 상업적 이용 무료)을 `next/font/local`로
  저장소 안(`app/fonts/`)에서 제공합니다. npm dependency를 추가하지 않습니다. 라이선스 원문을 `app/fonts/Pretendard-OFL.txt`로 함께 둡니다.
- Std 판은 자주 쓰는 한글 2,350자(KS X 1001)와 라틴 문자만 담아 약 290KB입니다. 전체 판(약 2MB)은 검색으로 들어와 37초 머무는
  모바일 사용자에게 너무 무겁습니다. 드문 글자는 대체 글꼴로 보입니다.
  `next/font/local`은 파일마다 `unicode-range`를 나눠 필요한 글자만 받는 방식(dynamic subset)을 지원하지 않아 이 방법을 택했습니다.
- 대체 글꼴: `-apple-system, BlinkMacSystemFont, "Apple SD Gothic Neo", "Noto Sans KR", sans-serif`.
  `Arial`을 맨 앞에 두지 않습니다. 영문 글꼴이 먼저 잡히면 한글은 기기마다 다른 글꼴로 보입니다.
- 날짜·시간·숫자가 세로로 줄 맞춰야 하는 곳(목록 메타, 운영 일정)에는 `tabular-nums`를 씁니다.

### 크기 단계

모바일 값을 기준으로 정하고, `lg`(1024px) 이상에서만 큰 제목을 키웁니다. 크기·줄 높이·굵기·자간 값은 `globals.css`의 `--text-*`에 있고,
class 하나로 함께 적용됩니다.

| class | 크기 / 줄 높이(px) | 굵기 | 쓰는 곳 |
| --- | --- | --- | --- |
| `text-display lg:text-display-lg` | 26 / 34 → 34 / 42 | 700 | 홈 첫 줄 소개 한 문장 |
| `text-title-1 lg:text-title-1-lg` | 22 / 30 → 30 / 38 | 700 | 상세 `h1`, 주제 페이지 `h1` |
| `text-title-2` | 19 / 27 | 600 | 구역 제목(`h2`) |
| `text-title-3` | 17 / 24 | 600 | 카드 묶음 안의 작은 제목 |
| `text-body` | 16 / 26 | 400 | 본문, 핵심 정보 값. 강조는 `font-semibold`를 더함 |
| `text-label` | 14 / 20 | 500 | 버튼, 칩, 폼 라벨 |
| `text-caption` | 13 / 18 | 400 | 메타(날짜·장소), 출처, 배지 |

- 목록 화면의 조작 글자도 `lg` 이상에서 한 단계 키웁니다(2026-11-06, PC에서 탭 글자가 작다는 피드백). 분야 탭 `text-label` → `text-title-3`,
  진행중/마감·정렬 `text-label` → `text-body`, 카드 제목 `text-body` → `text-title-3`, 카드 장소 `text-caption` → `text-label`.
  높이도 함께 늘려(분야 탭 52px, 진행중/마감 48px, 정렬 40px) 글자만 커져 답답해 보이지 않게 합니다.
- 굵기는 400·500·600·700만 씁니다. 800·900(`font-extrabold`, `font-black`)은 쓰지 않습니다.
- 13px보다 작은 글자를 쓰지 않습니다. 입력창 글자는 16px 이상입니다(iOS Safari는 16px 미만 입력창에 초점이 가면 화면을 확대합니다).
- 제목은 `letter-spacing: -0.02em`, 본문은 0입니다.
- 근거: 국내 스마트폰 실험에서 글자 크기와 행간이 클수록 가독성이 좋았고, 50~60대는 행간 영향을 더 크게 받았습니다
  ([윤종찬·하진영 2019](https://www.kci.go.kr/kciportal/ci/sereArticleSearch/ciSereArtiView.kci?sereArticleSearchBean.artiId=ART002433763), 20명 대상).
  KRDS는 본문 17px·행간 150% 내외를 씁니다. 표본이 작은 연구이므로 숫자보다 "작게 줄이지 않는다"는 방향을 따릅니다.

### 한글 줄바꿈

- 전역 기본: `word-break: keep-all; overflow-wrap: break-word;`. 단어 중간("생 / 활을")에서 끊기지 않게 하고,
  화면보다 긴 단어만 예외로 끊습니다. `overflow-wrap: anywhere`는 쓰지 않습니다.
- 제목은 `text-wrap: balance`, 본문 문단은 `text-wrap: pretty`를 씁니다. 지원하지 않는 브라우저에서는 무시되므로 안전합니다.
- URL·이메일처럼 띄어쓰기 없는 긴 문자열에만 `break-all`을 그 요소에 한정해 씁니다.
- `word-break: auto-phrase`는 실험 기능이라 쓰지 않습니다.
- 카드 제목(`text-body font-semibold`)은 2줄에서 자릅니다(`line-clamp-2`). 상세 제목은 자르지 않습니다.
- 본문 한 줄 최대 폭은 `40rem`입니다.

### 날짜·시간 표기

표기 함수의 원본은 `features/events/model/format.ts`입니다. 화면에서 직접 문자열을 만들지 않습니다.
목표 표기: 하루 `11.7 (토)`, 기간 `10.3 – 11.21`, 시간 `13:00–18:00`. 올해가 아닌 날짜가 섞이면 시작과 끝 모두 연도를 붙입니다(`2026.11.4 – 2027.1.21`, 어느 해인지 헷갈리지 않게, 2026-11-07 사용자 결정).

## Layout

### 반응형 기준

- **모바일 우선**: 기본 class가 360px 화면용입니다. 넓은 화면만 `sm:`(640), `md:`(768), `lg:`(1024), `xl:`(1280)로 덧붙입니다.
- 검증 폭은 **360, 412, 768, 1280**입니다. 360은 갤럭시 기본 폭이고, 국내 모바일은 Android가 약 64~66%입니다
  ([StatCounter, 2026-08](https://gs.statcounter.com/os-market-share/mobile/south-korea)).
- 콘텐츠 최대 폭 `70rem`(1120px). 좌우 여백 16px, `md` 이상 24px.
- 간격은 4px 단위(Tailwind `1`=4px)만 씁니다: 4, 8, 12, 16, 20, 24, 32, 40, 48. 구역 사이 간격은 모바일 32px, `lg` 48px입니다.
- **터치 영역은 44×44px 이상**이고, 붙어 있는 터치 요소 사이는 8px 이상 띄웁니다.
  (WCAG 2.2 최소 24px, Apple 44pt, Material 48dp 중 Apple 기준을 택했습니다.)
- 하단에 고정되는 요소는 `env(safe-area-inset-bottom)`만큼 여백을 더합니다.

### 페이지 구조

**공통 헤더**
- 높이 64px(`lg` 72px) 한 줄에 로고를 둡니다. 검색 버튼은 두지 않습니다(목록 위쪽에 검색창이 있어 겹쳤음, 2026-11-06).

## Elevation & Depth

- 기본은 평면 + 1px `line` 테두리입니다. 포스터 카드는 이미지에만 얇은 안쪽 테두리를 두고, 카드 바탕·그림자는 쓰지 않습니다.
- 그림자는 화면 위에 떠 있는 요소에만 `shadow-floating`으로 씁니다: 하단 고정 행동 바, 맨 위로 버튼, 시트·대화상자.
- 블러는 장식으로 쓰지 않습니다. 예외는 배너의 흐린 포스터 배경 하나입니다. 그 행사 포스터에서 나온 배경이라 장식이 아닙니다.
- hover 때 떠오르는 효과(`hover:-translate-y-*`, `hover:shadow-xl`)를 쓰지 않습니다. hover는 배경색 변화로 충분합니다.
- 겹침 순서: 헤더 30, 하단 고정 바 40, 시트 50, 본문 건너뛰기 링크 60.

## Shapes

Tailwind 기본 `rounded-sm`·`rounded-md`·`rounded-lg`와 겹치지 않게 역할 이름으로 둡니다. 값은 `globals.css`의 `--radius-*`에 있습니다.

| class | 크기 | 쓰는 곳 |
| --- | --- | --- |
| `rounded-badge` | 6px | 배지 |
| `rounded-control` | 10px | 버튼, 입력창 |
| `rounded-card` | 14px | 카드, 핵심 정보 블록, 시트·대화상자 |
| `rounded-full` | 원형 | 칩 |

- `rounded-2xl`(16px) 이상, `rounded-[2rem]`은 쓰지 않습니다. 모든 것을 같은 크게 둥근 모서리로 만들면 계층이 사라집니다.
- 목록 포스터는 4:5, `rounded-card`, `object-cover` + 위쪽 기준(`object-top`)으로 자릅니다. 세로 포스터는 보통 제목이 위에 있어서입니다.
- 포스터가 없는 행사는 분야와 상관없이 같은 **속초모아 기본 포스터**(`public/default-event-poster.svg`, `event-image-placeholder.tsx`)를 씁니다.
  분야 아이콘·이름만 두는 방식은 어색해서 바꿨습니다. 원래 포스터가 없는 행사이므로 "준비 중" 같은 문구는 쓰지 않습니다.
- 로컬 샘플 데이터는 `public/sample-events/`의 샘플 포스터(세로·정사각형·가로)를 씁니다(`supabase/seed.sql`).
- 아이콘은 **Lucide**(`lucide-react`, ISC 라이선스) 한 종류만 씁니다(2026-11-06 결정). 크기 20px, 선 굵기 1.75는 `components/ui/icon.ts`의 `iconProps`로 맞춥니다.
  앱을 만들면 같은 아이콘을 `lucide-react-native`로 씁니다. 손으로 그린 SVG나 다른 아이콘 세트를 섞지 않습니다.
  버전은 배포된 지 2주가 지난 것으로 정확히 고정합니다(지금 1.61.0). 아이콘만 있는 버튼에는 `aria-label`을 붙입니다.

### 공통 컴포넌트를 만드는 순서

1. **이 표에 먼저 규칙을 적습니다.** 표에 없는 부품이 필요하면 구현 전에 행을 추가하고, 그 변경을 같은 PR에 넣습니다.
2. 위치는 [architecture.md의 폴더](../docs/architecture.md#폴더) 규칙을 따릅니다. 두 개 이상의 feature가 쓰면 `components/ui/`,
   한 feature만 쓰면 `features/<도메인>/components/`에 둡니다. 화면마다 비슷한 부품을 따로 만들지 않습니다.
3. 변형(variant)과 크기 이름은 앱에서도 그대로 쓸 수 있게 플랫폼 중립적으로 짓습니다(`primary`, `md`. `card-hover` 같은 웹 용어는 쓰지 않음).
4. 지금 있는 공통 스타일 helper: `components/ui/button-styles.ts`, `components/ui/form-styles.ts`, `components/ui/form-field.tsx`.

### Dialog 규칙

화면을 덮는 안내·확인 창입니다. 첫 사용처는 관리자 삭제·재수집 허용 확인 창(`ConfirmDialog`)이고, 다음은 iOS "홈 화면에 추가" 안내입니다(알림 1단계, 웹 푸시와 함께 구현).

- **모양**: 모바일(`md` 미만)은 아래에서 올라오는 시트(bottom sheet), `md` 이상은 가운데 대화상자(최대 폭 `28rem`)입니다.
  `rounded-card`, `shadow-floating`을 쓰고, 시트는 아래쪽 safe-area 여백을 더합니다.
- **높이**: 화면 높이의 최대 `85svh`. 내용이 길면 창 안에서 스크롤하고, 제목 줄과 아래 버튼 줄은 고정합니다.
- **구현**: HTML `<dialog>`와 `showModal()`을 씁니다. 초점 가두기, `Esc`로 닫기, 뒤 화면 비활성(inert)을 브라우저가 처리하므로
  새 라이브러리를 들이지 않습니다.
- **접근성**: `aria-labelledby`로 제목을 연결합니다. 닫기 버튼은 오른쪽 위 44×44px이고 이름은 "닫기"입니다.
  닫히면 연 버튼으로 초점을 돌려줍니다.
- **버튼**: primary 하나("확인했어요" 등)와, 필요하면 보조 버튼 하나("다시 보지 않기")까지만 둡니다.
- **열리는 때**: 원칙적으로 사용자가 누른 동작의 결과로 엽니다. 페이지를 열 때 자동으로 띄우는 것은 정해진 조건(iOS 두 번째 방문 안내)이 있을 때만이며,
  닫으면 기록해서 같은 사람에게 반복해서 띄우지 않습니다.
- **배경**: `gray-900` 40% 반투명. 배경을 눌러도 닫힙니다. 단 입력 중인 폼이 있는 창은 배경 클릭으로 닫지 않습니다.
- **움직임**: 시트는 아래에서 200ms 안에 올라옵니다. `prefers-reduced-motion`이면 움직임 없이 나타납니다.
- **단계 안내형**(홈 화면 추가처럼 순서가 있는 안내): 단계마다 번호, 한 문장 설명, 그림을 둡니다. 세로로 이어 붙여 스크롤로 읽게 하고,
  넘기는 슬라이드(carousel)는 쓰지 않습니다. 그림은 실제 화면을 단순화한 일러스트나 직접 찍은 화면을 쓰고, 다른 회사 아이콘 원본을 복사하지 않습니다.

**접근성 이름 유지**: 개편해도 E2E가 찾는 역할·이름은 바꾸지 않습니다. 예: `navigation` "주요 메뉴"·"행사 상태"·"행사 정렬",
`search` "행사 검색", `region` "핵심 정보". 바꿔야 하면 test 변경을 먼저 사용자에게 묻습니다([루트 AGENTS.md의 검증 및 완료](../AGENTS.md#검증-및-완료)).

## Do's and Don'ts

AI가 만든 화면에서 반복되는 흔적을 금지 목록으로 둡니다. 근거: [superdesign](https://superdesign.dev/blog/why-ai-design-looks-generic),
[925studios](https://www.925studios.co/blog/ai-slop-design-tells)가 정리한 패턴과 2026-11-06 진단 결과(`font-black` 56곳, `rounded-2xl` 이상 61곳).

**하지 않습니다**
- 굵기 800·900, 모든 제목과 라벨을 가장 굵게 쓰기
- 그라데이션 배경·글자, 은은한 광채(radial glow), CSS로 그린 장식 도형, 이모지·기호(`≋`) 장식
- 크게 둥근 카드 3열 격자, 카드 안의 카드, hover 때 떠오르는 카드
- 한 항목에 배지 3개 이상
- 원색 팔레트 class(`teal-700`, `slate-600`)와 임의 hex(`text-[#07377a]`)
- 정보 없이 첫 화면을 차지하는 히어로
- placeholder만 있고 라벨이 없는 입력창
- 같은 화면의 primary 버튼 2개, 이유 없이 색이 다른 버튼

**합니다**
- 실제 데이터의 어려운 경우로 화면을 확인합니다: 긴 제목, 이미지 없음, 세로 포스터, 장소 미정, 마감, 기간이 긴 행사
- 화면마다 정보 우선순위를 먼저 정하고, 크기·굵기·위치로 계층을 만듭니다
- 빈 상태, 로딩, 오류 상태를 함께 설계합니다

## 앱 확장 대비

React Native 앱은 아직 정하지 않았습니다(알림을 통한 재방문이 동기). 지금 화면을 만들 때 아래만 지키면 나중에 옮기기 쉽습니다.

- 토큰은 역할 이름으로 씁니다. 앱을 시작할 때 둘 중 하나를 고릅니다:
  [Uniwind](https://uniwind.dev/)(Tailwind v4 `@theme`을 RN에서 그대로 사용) 또는
  [DTCG 2025.10](https://www.w3.org/community/design-tokens/2025/10/28/design-tokens-specification-reaches-first-stable-version/) JSON + Style Dictionary v5(한 원본에서 CSS와 RN 값을 함께 생성).
  NativeWind v5는 2026-09 기준 정식 출시 전이라 후보에서 뺍니다.
- hover로만 보이는 정보, 웹 전용 효과(`backdrop-blur` 등)에 의존하지 않습니다.
- 하단 고정 행동 바, 시트, 가로 스크롤 칩, 2열 카드처럼 앱에도 그대로 있는 패턴을 씁니다.
- 컴포넌트 이름과 variant(`Button` `primary`, `EventCard`)를 웹 용어(`card-hover` 등) 없이 짓습니다.
