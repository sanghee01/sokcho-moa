## Overview

### 누가, 어떻게 쓰나

GA4 보고서 개요(2026-10-09 ~ 2026-11-05) 기준입니다. 측정 설계는 [analytics-events.md](../docs/analytics-events.md)에 있습니다.

| 사실 | 값 | 설계에 주는 의미 |
| --- | --- | --- |
| 기기 | 모바일 84.6%, 데스크톱 14.6% | 360px 화면이 기준입니다. 데스크톱은 넓혀서 보여 주는 화면입니다 |
| 첫 유입 | 활성 사용자 741명 중 556명이 `m.search.naver.com` | 대부분 홈이 아니라 **상세·주제 페이지로 바로 들어옵니다**. 상세가 실제 첫 화면입니다 |
| 평균 참여 시간 | 37초 | 언제·어디서·얼마·신청 방법을 첫 화면에서 답해야 합니다 |
| 지역 | 서울 291, 속초 170, 부산 84 | 외지 방문객과 주민이 섞여 있습니다. "내가 가는 날 뭐 하지?"(날짜)로 찾습니다 |
| 재방문 | DAU/MAU 1.5% | 한 번 보고 떠납니다. 재방문 장치(알림)는 별도 과제입니다 |

### 원칙

1. **결정 정보 먼저.** 상세 페이지는 360×740 화면 안에 제목, 날짜, 장소, 신청·안내 버튼이 보여야 합니다.
2. **포스터가 보이게, 훑어보기 쉽게.** 행사 포스터는 정보의 큰 부분이라 목록에서도 크게 보여 줍니다(2열 카드). 날짜·장소는 항상 같은 자리에 둡니다.
   처음에는 작은 썸네일 목록 행을 썼지만, 64~80px로는 세로 포스터를 알아볼 수 없어 바꿨습니다(2026-11-06).
   모바일에서도 글을 처음부터 읽는 이해도는 데스크톱과 비슷하지만, 탐색·비교 작업은 모바일이 더 불리합니다
   ([NN/g, Reading Content on Mobile Devices, 2016](https://www.nngroup.com/articles/mobile-content/)).
3. **절제.** 색은 바다색 하나와 상태색만 씁니다. 굵기는 네 단계, 장식은 쓰지 않습니다. 강조는 크기·굵기·위치로 만듭니다.
4. **신뢰.** 공공 정보를 옮기는 서비스입니다. 출처와 "원문 확인" 안내가 늘 보여야 하고, 과장된 표현과 장식을 피합니다.
5. **모바일 우선, 앱으로 옮길 수 있게.** 웹에만 있는 상호작용(hover로만 보이는 정보 등)에 기대지 않습니다.

## Colors

### 원본 팔레트(primitive)

`sea`(속초 바다색)와 `gray`(바다색 쪽으로 아주 약하게 기운 회색) 두 가지입니다. 값은 `app/globals.css`에 있습니다.
컴포넌트에서 직접 쓰지 않고, 아래 역할 토큰을 거쳐서만 씁니다.

### 역할 토큰(semantic)

Tailwind v4의 `--color-*`로 정의되어 `bg-surface`, `text-content-muted`처럼 씁니다.

| 토큰 | 원본 | 쓰는 곳 |
| --- | --- | --- |
| `surface` | 흰색 | 페이지·카드 배경 |
| `surface-subtle` | `gray-50` | 구역 배경 |
| `surface-muted` | `gray-100` | 이미지 없는 포스터 자리, 비활성 배경 |
| `skeleton` | `gray-200` | 로딩 자리 |
| `content-strong` | `gray-900` | 제목, 선택된 칩 배경 |
| `content` | `gray-800` | 본문(전역 기본 글자색) |

| `line` | `gray-200` | 구분선, 포스터 테두리 |

| `on-image` / `image-scrim` | 흰색 / 55% 어두운 막 | 사진 위 글자 / 사진을 어둡게 덮는 막(배너) |

`brand-*`는 개편 전 컴포넌트(`components/ui/button-styles.ts`, `form-styles.ts`)가 쓰는 이름이라 `sea-*`를 가리키게 남겨 두었습니다.
2단계에서 역할 토큰으로 바꾸고 지웁니다. 새 코드에서는 쓰지 않습니다.

명도 대비(WCAG 2.x 계산식, 2026-11-06 계산): `content-subtle`/흰색 5.35, `content-subtle`/`surface-subtle` 5.02,
`primary`/흰색 6.05, `primary-text`/`primary-subtle` 7.16, `danger`/`danger-subtle` 5.75, `success`/`success-subtle` 5.71,
`line-input`/흰색 3.09. 글자는 4.5 이상, 입력창 테두리·아이콘 같은 UI 요소는 3 이상을 지킵니다.

### 행사 상태의 색

한 항목에 배지는 **최대 2개**입니다. 아래 우선순위로 고르고, 나머지는 메타 줄에 글자로 씁니다.

| 우선순위 | 상태 | 표현 |
| --- | --- | --- |
| 1 | 오늘 마감, 신청 D-1~D-3(KST 달력 날짜 기준) | `danger-subtle` 배지 + `danger` 글자 |
| 2 | 사전 신청(신청이 필요하고 마감까지 4일 이상 남았거나 마감일이 없음) | `success-subtle` 배지 + `success` 글자. "신청 가능"은 '신청해도 된다'로도 읽혀 쓰지 않습니다(2026-11-06) |
| 3 | 무료 | `line-strong` 테두리 배지 + `content-muted` 글자 |
| - | 진행 중, 예정 | 배지 없이 메타 줄의 날짜 앞에 글자로("진행 중 · 11.1 – 11.21") |
| - | 새로 올라옴 | 사이트에 공개된 지 7일이 지나지 않은 행사(`isRecentlyPublished`, 기준은 `published_at`). 포스터 오른쪽 위의 `NEW`(`primary` 바탕, 흰 글자). 상태 배지(최대 2개)와 따로 둡니다. 동그란 "N"은 촌스러워 보여 바꿨습니다(2026-11-06). 마감·종료된 행사에는 붙이지 않습니다 |
| - | 마감, 종료 | `surface-muted` 배지 + `content-subtle` 글자. 투명도(opacity)로 흐리게 하지 않습니다 |

## Typography

### 글꼴

- **Pretendard Std Variable**([SIL OFL 1.1](https://github.com/orioncactus/pretendard), 상업적 이용 무료)을 `next/font/local`로
  저장소 안(`app/fonts/`)에서 제공합니다. npm dependency를 추가하지 않습니다. 라이선스 원문을 `app/fonts/Pretendard-OFL.txt`로 함께 둡니다.
- Std 판은 자주 쓰는 한글 2,350자(KS X 1001)와 라틴 문자만 담아 약 290KB입니다. 전체 판(약 2MB)은 검색으로 들어와 37초 머무는
  모바일 사용자에게 너무 무겁습니다. 드문 글자는 대체 글꼴로 보입니다.
  `next/font/local`은 파일마다 `unicode-range`를 나눠 필요한 글자만 받는 방식(dynamic subset)을 지원하지 않아 이 방법을 택했습니다.
- 대체 글꼴: `-apple-system, BlinkMacSystemFont, "Apple SD Gothic Neo", "Noto Sans KR", sans-serif`.
  `Arial`을 맨 앞에 두지 않습니다. 영문 글꼴이 먼저 잡히면 한글은 기기마다 다른 글꼴로 보입니다.
- 날짜·시간·숫자가 세로로 줄 맞춰야 하는 곳(목록 메타, 운영 일정)에는 `tabular-nums`를 씁니다.

### 크기 단계

모바일 값을 기준으로 정하고, `lg`(1024px) 이상에서만 큰 제목을 키웁니다. 크기·줄 높이·굵기·자간 값은 `globals.css`의 `--text-*`에 있고,
class 하나로 함께 적용됩니다.

| class | 크기 / 줄 높이(px) | 굵기 | 쓰는 곳 |
| --- | --- | --- | --- |
| `text-display lg:text-display-lg` | 26 / 34 → 34 / 42 | 700 | 홈 첫 줄 소개 한 문장 |
| `text-title-1 lg:text-title-1-lg` | 22 / 30 → 30 / 38 | 700 | 상세 `h1`, 주제 페이지 `h1` |
| `text-title-2` | 19 / 27 | 600 | 구역 제목(`h2`) |
| `text-title-3` | 17 / 24 | 600 | 카드 묶음 안의 작은 제목 |
| `text-body` | 16 / 26 | 400 | 본문, 핵심 정보 값. 강조는 `font-semibold`를 더함 |
| `text-label` | 14 / 20 | 500 | 버튼, 칩, 폼 라벨 |
| `text-caption` | 13 / 18 | 400 | 메타(날짜·장소), 출처, 배지 |

- 목록 화면의 조작 글자도 `lg` 이상에서 한 단계 키웁니다(2026-11-06, PC에서 탭 글자가 작다는 피드백). 분야 탭 `text-label` → `text-title-3`,
  진행중/마감·정렬 `text-label` → `text-body`, 카드 제목 `text-body` → `text-title-3`, 카드 장소 `text-caption` → `text-label`.
  높이도 함께 늘려(분야 탭 52px, 진행중/마감 48px, 정렬 40px) 글자만 커져 답답해 보이지 않게 합니다.
- 굵기는 400·500·600·700만 씁니다. 800·900(`font-extrabold`, `font-black`)은 쓰지 않습니다.
- 13px보다 작은 글자를 쓰지 않습니다. 입력창 글자는 16px 이상입니다(iOS Safari는 16px 미만 입력창에 초점이 가면 화면을 확대합니다).
- 제목은 `letter-spacing: -0.02em`, 본문은 0입니다.
- 근거: 국내 스마트폰 실험에서 글자 크기와 행간이 클수록 가독성이 좋았고, 50~60대는 행간 영향을 더 크게 받았습니다
  ([윤종찬·하진영 2019](https://www.kci.go.kr/kciportal/ci/sereArticleSearch/ciSereArtiView.kci?sereArticleSearchBean.artiId=ART002433763), 20명 대상).
  KRDS는 본문 17px·행간 150% 내외를 씁니다. 표본이 작은 연구이므로 숫자보다 "작게 줄이지 않는다"는 방향을 따릅니다.

### 한글 줄바꿈

- 전역 기본: `word-break: keep-all; overflow-wrap: break-word;`. 단어 중간("생 / 활을")에서 끊기지 않게 하고,
  화면보다 긴 단어만 예외로 끊습니다. `overflow-wrap: anywhere`는 쓰지 않습니다.
  예외: 2줄에서 자르는 카드 제목은 `wrap-anywhere`로 한 줄보다 긴 단어를 줄 끝에서 끊습니다. 끊지 않는 브라우저에서 "…"가 들어갈 자리가 없어
  긴 단어("공연장예술단체육성지원사업")가 통째로 사라지고 "2026 / …"만 보였습니다(2026-11-21 사용자 결정. 글자 단위 줄바꿈 대신 단어 단위는 유지).
- 제목은 `text-wrap: balance`, 본문 문단은 `text-wrap: pretty`를 씁니다. 지원하지 않는 브라우저에서는 무시되므로 안전합니다.
- URL·이메일처럼 띄어쓰기 없는 긴 문자열에만 `break-all`을 그 요소에 한정해 씁니다.
- `word-break: auto-phrase`는 실험 기능이라 쓰지 않습니다.
- 카드 제목(`text-body font-semibold`)은 2줄에서 자릅니다(`line-clamp-2`). 상세 제목은 자르지 않습니다.
- 본문 한 줄 최대 폭은 `40rem`입니다.

### 날짜·시간 표기

표기 함수의 원본은 `features/events/model/format.ts`입니다. 화면에서 직접 문자열을 만들지 않습니다.
목표 표기: 하루 `11.7 (토)`, 기간 `10.3 – 11.21`, 시간 `13:00–18:00`. 올해가 아닌 날짜가 섞이면 시작과 끝 모두 연도를 붙입니다(`2026.11.4 – 2027.1.21`, 어느 해인지 헷갈리지 않게, 2026-11-07 사용자 결정).

## Layout

### 반응형 기준

- **모바일 우선**: 기본 class가 360px 화면용입니다. 넓은 화면만 `sm:`(640), `md:`(768), `lg:`(1024), `xl:`(1280)로 덧붙입니다.
- 검증 폭은 **360, 412, 768, 1280**입니다. 360은 갤럭시 기본 폭이고, 국내 모바일은 Android가 약 64~66%입니다
  ([StatCounter, 2026-08](https://gs.statcounter.com/os-market-share/mobile/south-korea)).
- 콘텐츠 최대 폭 `70rem`(1120px). 좌우 여백 16px, `md` 이상 24px.

8. "무료" 필터는 두지 않습니다(2026-11-07 사용자 결정: 카드의 무료 배지로 충분하고, 무료 여부가 비어 있는 수집 행사가 많아 걸러 내면 빠짐). 예전 `free` URL 값을 일부러 빼는 코드(`browse-url.ts`의 `DROPPED_PARAMS`)는 무료 필터를 지운 커밋(`9238cb3`, 2026-07-20)에서 함께 넣었습니다. 지운 필터의 옛 값이 새로 만드는 링크와 검색 숨김 입력에 따라붙지 않게 합니다.

**월별 행사** (`/months/YYYY-MM`): "11월 속초 행사"처럼 기간으로 찾는 검색에 답하는 페이지입니다(2026-11-15 사용자 결정).
화면에는 제목과 행사 카드만 둡니다. 행사 수 같은 요약 문장은 검색 결과 설명(meta description)과 구조화 데이터에만 씁니다(`buildEventMonthDescription`, 2026-11-15 사용자 결정).
1. 맨 위 `‹ 2026년 11월 ›`: 가운데 `h1`(큰 줄 "2026년 11월" `title-1` + 작은 줄 "속초 행사 일정", 분야를 고르면 "속초 교육 일정" `label` `content-muted`), 양 끝에 44px 정사각형 화살표(`navigation` "다른 달", 흰 바탕 + `line-strong` 테두리). 열지 않는 달 쪽 화살표는 두지 않고, 고른 분야는 달을 넘겨도 유지합니다. 연·월 드롭다운은 열리는 달이 몇 개뿐이라 쓰지 않습니다(2026-11-15 사용자 결정).
2. "진행 중·예정 행사" → "끝난 행사" 두 구역(`h2` `title-2`). 카드는 목록과 같은 `EventCard` 격자이고 구역마다 시작일순입니다. 신청만 마감된 행사는 행사가 열리고 있어 앞 구역에 둡니다.
3. 열리는 달: 이번 달·다음 달은 행사가 없어도 열고(빈 상태: "아직 올라온 일정이 없어요" + "진행 중인 행사 보기"), 지난 달은 행사가 있을 때만, 다다음 달부터는 404입니다. sitemap에는 이번 달·다음 달만 넣습니다.
   달·분야 페이지(`/months/YYYY-MM/<분야>`)는 "속초 11월 교육" 같은 검색에 답합니다. 제목은 "2026년 11월 속초 교육 일정"이고, 행사가 없으면 화면은 열되 검색에 올리지 않습니다(`noindex`). sitemap에는 이번 달·다음 달 중 행사가 있는 조합만 넣습니다(2026-11-15 사용자 결정).
4. 주간("이번 주·이번 주말")은 따로 페이지를 만들지 않고, 필요하면 이번 달 페이지 안의 칩으로 더합니다. 배포 뒤 GA에서 월별 페이지 사용을 보고 정합니다(2026-11-15 사용자 결정). 주간 페이지는 1년에 52개의 얇은 페이지가 되어 월 페이지와 겹칩니다.

**지도** (`/map`): 지금 신청·참여할 수 있는 행사를 장소별 핀으로 보여 줍니다(2026-11-16 사용자 결정: 네이버 지도. 포스터 핀은 2026-11-21에 위치·개수·이름 핀으로 바꿈).
1. 헤더 아래를 지도가 채웁니다(`100svh - 헤더 높이`). 페이지 중간에 지도를 끼우면 화면 스크롤과 지도 끌기가 부딪혀서입니다. 제목(`h1`)은 화면 읽기용(`sr-only`)입니다.
   공통 푸터는 두지 않습니다(`data-full-screen-map`, 2026-11-16 사용자 결정: 푸터가 지도 아래 붙으면 칩·헤더를 끌 때 페이지가 스크롤돼 지도가 밀렸음).
   지도 SDK를 불러오는 동안은 가운데에 스피너만 둡니다(`role="status"` "지도를 불러오는 중", 2026-11-16 사용자 결정).
2. **레이어 전환**(`group` "지도 레이어": 행사 | 가볼만한 곳)은 두 칸 **밑줄 탭**이고, 그 아래 분야 칩(`group` "지도 분야", FilterChip 모양, `aria-pressed`)입니다. 한 번에 한 레이어만 보여 범례 없이도 핀이 무엇인지 압니다.
   진한 두 칸 버튼은 실행 버튼처럼 무거워 보여 밑줄 탭으로 바꿨습니다(2026-11-21 사용자 결정: 시안 B). 칩 사이 간격은 두 레이어가 같습니다(모바일 4px, `md` 이상 8px).
   모바일: 지도 위 전체 폭. 행사 분야는 7칸이 한 줄에 들어가고, 가볼만한 곳 분류는 이름이 길어 가로로 밀어 봅니다(이 칩 줄만의 예외).
   `md` 이상: 왼쪽 320px 판(`MapPinList`) 맨 위에 탭과 칩, 그 아래 지금 레이어·분야의 **장소 목록**(이름 + "행사 N개" 또는 분류)이 있고 오른쪽을 지도가 채웁니다.
   목록을 누르면 핀을 누른 것과 같이 장소 카드가 열립니다. 카카오맵·네이버 지도 PC 방식이고, 판이 고정이라 레이어를 바꿔도 컨트롤 자리가 움직이지 않습니다(2026-11-21 사용자 결정: 시안 D). 두 레이어의 분야가 달라 칩 하나로 합치지는 않습니다. 레이어는 주소 `?layer=places`, 분야는 `?category=`에 남고, 레이어를 바꾸면 분야와 고른 장소를 비웁니다.
   가볼만한 곳 핀은 행사 핀과 같은 몸통·꼬리 구조에 개수 대신 핀 아이콘(`accent` 차콜)이고, 누르면 사진·분류·이름·요금과 "자세히 보기"가 있는 장소 카드가 열립니다.
3. 핀은 행사가 아니라 **장소 단위**입니다(`selectEventMapPlaces`, 좌표 30m 안은 같은 장소). 한 시설에 행사가 몰려 행사마다 찍으면 겹쳐 누를 수 없어서입니다.
   마커는 흰 몸통 안의 `primary` **행사 개수 동그라미**(몸통 44px로 누름 최소 크기를 지킴, 동그라미 36px, 행사가 하나여도 1) + 아래 꼬리 + 꼬리 끝 `primary` 위치 점(10px, 흰 테두리)이고, 점의 가운데가 장소 좌표입니다.
   자리가 있으면 몸통 옆에 **장소 이름**(`caption` semibold, 한 줄 말줄임, 최대 144px)을 붙여 알약이 됩니다. 포스터는 지도에 올리지 않고 장소 카드에서 보입니다.
   예전 포스터 핀(48~72px 액자)은 문화예술회관·엑스포 일대처럼 시설이 몰린 곳에서 서로 가려 읽기도 누르기도 어려웠습니다(2026-11-21 사용자 피드백. NN/g [Mobile Maps and Locations](https://www.nngroup.com/articles/mobile-maps-locations/): 겹친 작은 핀은 손가락으로 고르기 어려움).
   이름은 다른 마커와 겹치지 않을 때만 보입니다(`selectMapLabelIds`): 고른 장소 → 행사가 많은 장소 순서로 자리를 잡고, 이미 놓인 이름이나 다른 마커의 몸통을 덮는 이름은 숨깁니다. 고른 장소의 이름은 늘 보입니다.
   지도 서비스의 겹침 관리 방식을 따랐습니다([Google Maps marker collision](https://developers.google.com/maps/documentation/javascript/examples/marker-collision-management): 겹치면 우선순위 낮은 표시를 숨김). 확대하면 마커 사이가 벌어져 이름이 더 보입니다. 지도 움직임이 끝날 때(`idle`) 다시 계산합니다.
   시내 전체를 볼 때 몸통끼리 겹치는 장소는 **묶음 마커** 하나로 합칩니다(`clusterMapMarkers`, [Google Maps Marker Clustering](https://developers.google.com/maps/documentation/javascript/marker-clustering)). 몸통만 남겨도 문화예술회관·교동 일대는 동그라미끼리 겹쳐 이름이 하나도 보이지 않았습니다(2026-11-21).
   묶음은 행사가 가장 많은 장소 자리에 채운 `primary` 동그라미(44px, 옅은 테두리, 위치 점 없음)로 묶인 장소들의 행사 수 합계를 보이고, 이름은 "장소 N곳, 행사 M개, 눌러서 확대"입니다. 누르면 묶인 장소가 다 보이게 확대해 풀립니다.
   확대 16까지만 묶고 17부터는 모두 따로 보입니다(가까운 장소끼리 계속 묶여 풀 수 없게 되지 않게). 고른 장소는 묶지 않습니다.
   고른 장소는 몸통을 `primary`로 채우고(개수 동그라미는 흰색) 다른 마커 위로 올립니다. 겹친 마커는 남쪽(화면 아래)을 위에 쌓고, 누름 영역은 보이는 몸통(알약)뿐입니다(투명한 영역이 옆 마커의 누름을 가로채지 않게, 2026-11-16 사용자 피드백).
   핀은 버튼이라 키보드로 고를 수 있고 이름은 "장소, 행사 N개"입니다. Tab 순서는 화면 순서(북쪽에서 남쪽, 서쪽에서 동쪽)입니다. 좌표가 없는 행사("○○ 일원", 여러 장소)와 속초·고성·양양 밖 좌표는 지도에 올리지 않습니다.
   행사에 좌표가 없으면 장소 사전(`data/venues.json`)의 시설 좌표를 쓰고, 카드 제목도 사전의 시설 이름입니다(2026-11-16: 저장된 좌표만으로는 진행 중 행사 22개 중 1개만 지도에 올랐음).
4. 핀을 누르면 장소 카드가 열립니다(장소를 고른 채 지도의 빈 곳을 누르면 카드를 닫고 고른 표시와 핀 초점을 없앱니다, 2026-11-21 사용자 요청. 마우스로 닫은 것이라 닫기 버튼과 달리 핀으로 초점을 돌려주지 않습니다): 모바일은 지도 아래쪽 시트(최대 60%), `md` 이상은 왼쪽 목록 판 바로 오른쪽, 지도 위에 떠 있는 24rem 판. 지도는 계속 움직일 수 있습니다(모달 아님). 제목은 시설 이름, 내용은 목록과 같은 `EventCard` 2열입니다.
   핀이 카드나 화면 가장자리에 가릴 때만 카드에 가리지 않는 곳의 가운데로 한 번 옮기고(동작 줄이기 설정이면 애니메이션 없이), 잘 보이는 핀은 지도를 움직이지 않습니다. 카드를 닫아도 지도는 그대로입니다.
   예전에는 고를 때마다 지도 안쪽 여백(padding)을 카드 크기로 바꾸고 핀을 가운데로 끌어와, 여백을 바꾸는 순간 지도가 밀린 뒤 다시 움직였고 닫을 때도 밀렸습니다(2026-11-21 사용자 피드백: 덜컹거려 어지러움).
   지도 상자는 스크롤되지 않게 막습니다(가장자리 핀에 초점이 가면 브라우저가 숨긴 영역을 스크롤해 SDK 모르게 지도가 밀렸음).
   카드를 누르면 상세 페이지로 갑니다. 상세를 시트에 통째로 넣지 않습니다([NN/g Bottom Sheets, 2023](https://www.nngroup.com/articles/bottom-sheet/): 시트로 페이지 이동을 대신하지 않기).
   고른 장소는 주소 `?place=`에 남아 상세에서 뒤로 오면 같은 카드가 열려 있고, 브라우저 뒤로 가기·닫기 버튼(44px, "닫기")·카드 안에서 Esc로 카드를 닫습니다. 카드를 닫아도 기록이 한 칸 남지 않고, 연 뒤 바꾼 분야는 남습니다.
   장소의 주소 값(`?place=`)은 사전 시설이면 시설 좌표라 행사가 끝나도 바뀌지 않습니다. 지도에 없는 장소가 주소에 있으면 주소에서 뺍니다.
5. 처음에는 핀이 모두 보이게 맞추고(최대 확대 15), 분야를 바꾸면 다시 맞춥니다. 지도는 속초·고성·양양 밖으로 옮겨지지 않고 확대 10보다 작게 줄지 않습니다. 확대·축소 버튼을 오른쪽 위(분야 칩 아래)에 둡니다(끌기 대신 누르는 방법, WCAG 2.5.7). 오른쪽 가운데는 모바일 장소 카드에 가려졌고, 왼쪽은 `md` 이상 장소 카드 자리입니다(2026-11-16 사용자 결정).
6. 빈 상태: 고른 분야에 핀이 없으면 "지도에 표시할 ○○ 일정이 없어요" + "전체 보기", 핀이 하나도 없으면 "행사 목록 보기". 지도를 불러오지 못하면(키 없음, 인증 실패) "지금은 지도를 볼 수 없어요" + "행사 목록 보기".

**가볼만한 곳 목록** (`/places`, `/places/category/<분류>`): 해변·호수 같은 명소와 워터파크·전시관·전망대처럼 언제든 갈 수 있는 곳의 목록입니다(2026-11-21 사용자 결정). 구매 기능은 없고 공식 홈페이지·예매처로 보냅니다.

   사진은 줄 **오른쪽 80px 정사각 썸네일**이고, 쓸 수 있는 사진이 없는 장소는 썸네일 자리를 빼고 글이 폭 전체를 씁니다(2026-11-21 사용자 요청: 실제 사진을 싣는다). 사진이 없는 줄에도 화살표(>)를 두지 않습니다. 사진 있는 줄과 모양이 달라졌고, 줄 전체가 링크라는 것은 hover 배경과 목록 모양으로 알 수 있습니다(2026-11-21 사용자 피드백).

   빈 상자·아이콘·기본 이미지로 채우지 않고, 그 장소가 아닌 사진(속초 일반 풍경, 스톡, AI 생성)도 쓰지 않습니다. 장식 사진은 건너뛰고 정보가 있는 사진만 봅니다([NN/g Photos as Web Content](https://www.nngroup.com/articles/photos-as-web-content/)).
3. 한 줄에 이름, 한 줄 소개(두 줄까지), 요금 대표값 · 조건 태그(실내·아이와·무료·예약 필수)를 둡니다. 모든 줄은 최소 높이 128px로 같게 맞추고, 링크가 칸 전체를 채워 `md` 두 열에서도 hover 배경 아래가 비지 않습니다(2026-11-21 사용자 피드백: 사진·요금 유무로 줄 높이가 달랐음). 목록에 가격이 없으면 하나씩 열어 비교해야 합니다([Baymard 2023](https://baymard.com/blog/tours-and-experiences-launch)).
   평점·후기 수·조회수는 쓰지 않습니다(직접 받은 후기가 없고, 다른 사이트 평점을 옮겨 싣지 않음). 운영 상태는 정상이 아닐 때만 배지로 보입니다(시즌 휴장, 임시 휴업). 운영을 끝낸 곳은 목록에서 뺍니다.

**가볼만한 곳 상세** (`/places/<slug>`): 행사와 달리 끝나는 날이 없어 정보가 조용히 낡습니다. 그래서 **언제 확인한 정보인지**를 드러내는 것이 이 화면의 원칙입니다.
1. 분류 · 조건 태그 한 줄(`caption`, `primary-text`)과 운영 상태 배지(정상이 아닐 때만) → `h1` → 한 줄 소개 → 운영 상태 안내(있을 때만. 날짜가 든 안내는 끝나는 날(`status_note_until`)이 지나면 숨김, 2026-11-22).
2. 버튼: `공식 홈페이지`(primary), `예매하기`(accent, 예매처가 있을 때만), `길찾기`(tonal). 행사 상세의 `행사 안내`·`신청·예매`와 같은 색 규칙입니다. 하단 고정 바는 쓰지 않고 제목 바로 아래에 둡니다.
   그 아래에 **대표 사진**(`PlacePhotoFigure`, 3:2, 본문 폭)과 출처 한 줄을 둡니다. 사진을 맨 위에 두지 않는 이유: 사진 없는 장소와 윗부분이 같아지고, 검색으로 들어온 방문자가 제목으로 맞는 페이지인지 먼저 확인하며,
   이 화면의 목표가 핵심 정보와 공식 사이트로 가는 버튼이기 때문입니다([NN/g Image-Focused Design](https://www.nngroup.com/articles/image-focused-design/): 큰 사진은 핵심 기능을 첫 화면 밖으로 밀어냄). 구석구석·비짓제주·카카오맵 같은 정보 서비스도 제목 다음에 사진을 둡니다. 사진 없는 장소는 사진 블록을 통째로 뺍니다.

"운영시간과 요금은 시즌에 따라 바뀝니다…" 문장은 거의 모든 장소에 되풀이되고 목록 위 안내 띠와 같은 말이라 두지 않습니다(2026-11-21 사용자 결정) → 근처에서 열리는 행사(`EventCard`, 300m 안) → 같은 분류의 다른 곳 → "목록으로 돌아가기" 버튼(`tonal`, 행사 상세와 같음). 맨 위에는 "‹ 목록으로 돌아가기" 글자 링크가 있습니다.
   확인일은 실제로 다시 확인했을 때만 바꿉니다([Stanford Web Credibility Guidelines](https://credibility.stanford.edu/guidelines/index.html) 8번, [Fogg 외 2001](https://credibility.stanford.edu/pdf/p61-fogg.pdf): 갱신된 사이트 +1.55, 갱신 안 되는 사이트 −1.67).

**통합 검색** (`/search?q=&type=`): 헤더 돋보기(`lg` 미만)·검색창(`lg` 이상)에서 옵니다(2026-11-21 사용자 결정). 검색어 없이 들어오면 입력창에 바로 커서가 있고, 결과 화면에서는 키보드가 결과를 가리지 않게 커서를 넣지 않습니다.
- 검색어가 없으면 **최근 검색어**(최신 10개, 줄마다 다시 검색 링크와 삭제 버튼, "전체 삭제")를 보이고, 기록이 없으면 "최근 검색 내역이 없어요."만 둡니다(2026-11-21 사용자 결정: 인기 행사 추천은 어색해 야놀자처럼 기록을 보임). 기록은 이 기기의 localStorage에만 둡니다(`components/layout/recent-search-storage.ts`). 검색어가 있으면 범위 칩(`navigation` "검색 범위": 전체 · 행사 · 가볼만한 곳, 각 건수)과 결과입니다.
  기본은 "전체"이고 결과 화면에서 좁힙니다([NN/g Scoped Search](https://www.nngroup.com/articles/scoped-search/)). "전체"에서는 행사 4개·장소 5곳까지만 보이고 "모두 보기"로 그 종류만 봅니다.

- 검색을 제출하면 결과를 기다리는 동안 입력창의 돋보기가 스피너로 바뀝니다(헤더 검색창도 같음, `components/layout/site-search-form.tsx`). 공개 화면이라 로딩 화면(`loading.tsx`)은 두지 않습니다.

**공지** (`/notices`, `/notices/<id>`): 목록은 종류 · 날짜(`caption`)와 제목(`title-3`)만 있는 줄이고, 누르면 글 페이지로 갑니다(최대 폭 `48rem`). 목록 안에서 펼치는 아코디언은 긴 글을 펼치면 아래 목록이 끝없이 밀리고 글마다 주소가 없어 공유·검색이 안 돼 쓰지 않습니다(2026-11-21).

**제보·의견 폼**: 한 열, 최대 폭 `40rem`, 라벨은 입력창 위, 입력 높이 48px, 오류는 해당 필드 바로 아래.

**관리자**: 데스크톱 기준으로 만들어도 됩니다. 768px에서 가로로 넘치지만 않으면 됩니다(E2E `tests/e2e/admin-responsive.spec.ts`).
- 색·글자·모서리는 공개 화면과 같은 역할 토큰을 씁니다. 표처럼 넓은 내용은 자기 안에서만 가로로 밀립니다(`overflow-x-auto`).
- 머리글은 밝은 회색 띠(`surface-subtle`)입니다. 예전의 어두운 머리글은 토큰으로 표현할 수 없는 반투명 흰색을 써서 바꿨습니다(2026-11-06).
- 경고색 토큰이 없어 제보·의견의 "검토 대기"는 `primary-subtle`, "검토 완료"는 `success-subtle`, "철회"는 `surface-muted`로 구분합니다.

## Elevation & Depth

- 기본은 평면 + 1px `line` 테두리입니다. 포스터 카드는 이미지에만 얇은 안쪽 테두리를 두고, 카드 바탕·그림자는 쓰지 않습니다.
- 그림자는 화면 위에 떠 있는 요소에만 `shadow-floating`으로 씁니다: 하단 고정 행동 바, 맨 위로 버튼, 시트·대화상자.
- 블러는 장식으로 쓰지 않습니다. 예외는 흐린 포스터 배경 하나입니다(배너와 상세가 함께 쓰는 `features/events/components/poster-backdrop.tsx`). 그 행사 포스터에서 나온 배경이라 장식이 아닙니다.
- hover 때 떠오르는 효과(`hover:-translate-y-*`, `hover:shadow-xl`)를 쓰지 않습니다. hover는 배경색 변화로 충분합니다.
- 겹침 순서: 헤더 30, 하단 고정 바 40, 시트 50, 본문 건너뛰기 링크 60.

## Shapes

Tailwind 기본 `rounded-sm`·`rounded-md`·`rounded-lg`와 겹치지 않게 역할 이름으로 둡니다. 값은 `globals.css`의 `--radius-*`에 있습니다.

| class | 크기 | 쓰는 곳 |
| --- | --- | --- |
| `rounded-badge` | 6px | 배지 |
| `rounded-control` | 10px | 버튼, 입력창 |
| `rounded-card` | 14px | 카드, 핵심 정보 블록, 시트·대화상자 |
| `rounded-full` | 원형 | 칩 |

- `rounded-2xl`(16px) 이상, `rounded-[2rem]`은 쓰지 않습니다. 모든 것을 같은 크게 둥근 모서리로 만들면 계층이 사라집니다.
- 목록 포스터는 4:5, `rounded-card`, `object-cover` + 위쪽 기준(`object-top`)으로 자릅니다. 세로 포스터는 보통 제목이 위에 있어서입니다.
- 포스터가 없는 행사는 분야와 상관없이 같은 **속초모아 기본 포스터**(`public/brand/default-event-poster.svg`, `event-image-placeholder.tsx`)를 씁니다.
  분야 아이콘·이름만 두는 방식은 어색해서 바꿨습니다. 원래 포스터가 없는 행사이므로 "준비 중" 같은 문구는 쓰지 않습니다.
- 로컬 샘플 데이터는 `public/sample-events/`의 샘플 포스터(세로·정사각형·가로)를 씁니다(`supabase/seed.sql`).
- 아이콘은 **Lucide**(`lucide-react`, ISC 라이선스) 한 종류만 씁니다(2026-11-06 결정). 크기 20px, 선 굵기 1.75는 `components/ui/icon.ts`의 `iconProps`로 맞춥니다.
  앱을 만들면 같은 아이콘을 `lucide-react-native`로 씁니다. 손으로 그린 SVG나 다른 아이콘 세트를 섞지 않습니다.
  버전은 배포된 지 2주가 지난 것으로 정확히 고정합니다(지금 1.61.0). 아이콘만 있는 버튼에는 `aria-label`을 붙입니다.

### 공통 컴포넌트를 만드는 순서

1. **이 표에 먼저 규칙을 적습니다.** 표에 없는 부품이 필요하면 구현 전에 행을 추가하고, 그 변경을 같은 PR에 넣습니다.

3. 변형(variant)과 크기 이름은 앱에서도 그대로 쓸 수 있게 플랫폼 중립적으로 짓습니다(`primary`, `md`. `card-hover` 같은 웹 용어는 쓰지 않음).

| **SearchField** | 둥근(`rounded-full`) 입력창, 글자 16px, 테두리 `line-input`, 왼쪽 돋보기. 헤더(`md` 이상, 높이 44px)와 검색 화면(`components/layout/site-search-field.tsx`, 높이 48px, 지우기 버튼)이 같은 모양이고 `search` 역할 이름은 "사이트 검색"입니다. 일반 GET 폼이라 `/search?q=`로 갑니다 |
| **EmptyState** | 실제 상황을 말하는 한 문장 + 갈 만한 곳 하나(보조 버튼). 사용자가 하지 않은 일을 시키지 않습니다. 검색 결과 없음 → "검색 지우기", 마감 탭이 빔 → "진행 중인 ○○ 보기", 분야에 일정이 없음 → "전체 행사 보기", 예전 주소의 조건 → "조건 지우기". 분야 이름 뒤에는 받침에 따라 바뀌는 조사를 붙이지 않고 "기록이", "일정이" 같은 고정된 말을 씁니다 |
| **Skeleton** | 실제 내용과 같은 자리를 차지하는 자리 표시(제보 폼, 관리자 화면). 공개 목록·상세에는 두지 않습니다. 크롤러가 HTML에서 본문을 읽도록 `loading.tsx`를 빼고, 이동 중 표시는 `TransitionLink`로 합니다(2026-11-15) |
| **Dialog**(대화상자·시트) | 아래 [Dialog 규칙](#dialog-규칙). 되돌릴 수 없는 동작의 확인은 `components/ui/confirm-dialog.tsx`(`ConfirmDialog`, `ConfirmDialogActions`, `ConfirmDialogButton`) 하나만 씁니다(관리자 삭제·재수집 허용, 2026-11-06 사용자 결정). 브라우저 기본 `confirm()`과 "확인했습니다" 체크박스는 쓰지 않습니다 |

### Dialog 규칙

화면을 덮는 안내·확인 창입니다. 첫 사용처는 관리자 삭제·재수집 허용 확인 창(`ConfirmDialog`)이고, 다음은 iOS "홈 화면에 추가" 안내입니다(알림 1단계, 웹 푸시와 함께 구현).

- **모양**: 모바일(`md` 미만)은 아래에서 올라오는 시트(bottom sheet), `md` 이상은 가운데 대화상자(최대 폭 `28rem`)입니다.
  `rounded-card`, `shadow-floating`을 쓰고, 시트는 아래쪽 safe-area 여백을 더합니다.
- **높이**: 화면 높이의 최대 `85svh`. 내용이 길면 창 안에서 스크롤하고, 제목 줄과 아래 버튼 줄은 고정합니다.
- **구현**: HTML `<dialog>`와 `showModal()`을 씁니다. 초점 가두기, `Esc`로 닫기, 뒤 화면 비활성(inert)을 브라우저가 처리하므로
  새 라이브러리를 들이지 않습니다.
- **접근성**: `aria-labelledby`로 제목을 연결합니다. 닫기 버튼은 오른쪽 위 44×44px이고 이름은 "닫기"입니다.
  닫히면 연 버튼으로 초점을 돌려줍니다.
- **버튼**: primary 하나("확인했어요" 등)와, 필요하면 보조 버튼 하나("다시 보지 않기")까지만 둡니다.
- **열리는 때**: 원칙적으로 사용자가 누른 동작의 결과로 엽니다. 페이지를 열 때 자동으로 띄우는 것은 정해진 조건(iOS 두 번째 방문 안내)이 있을 때만이며,
  닫으면 기록해서 같은 사람에게 반복해서 띄우지 않습니다.
- **배경**: `gray-900` 40% 반투명. 배경을 눌러도 닫힙니다. 단 입력 중인 폼이 있는 창은 배경 클릭으로 닫지 않습니다.
- **움직임**: 시트는 아래에서 200ms 안에 올라옵니다. `prefers-reduced-motion`이면 움직임 없이 나타납니다.
- **이미지 보기**(상세 포스터 크게 보기, `features/events/components/detail/event-poster-viewer.tsx`): 위 모양·높이·버튼 규칙의 예외로 화면 전체를 `image-scrim-strong`으로 덮고
  포스터를 원래 비율로 화면 안에 맞춥니다(작은 원본은 늘리지 않음). 닫기 버튼은 포스터와 겹치지 않는 윗줄 오른쪽에 두고, 진한 반투명 원 + 흰 테두리로
  어떤 포스터 색 위에서도 보이게 합니다. 포스터 바깥을 누르거나 Esc·뒤로가기로 닫히며, 뒤로가기로 닫아도 페이지를 떠나지 않습니다. 움직임은 200ms 나타나기만 씁니다(2026-11-18 사용자 결정).
- **단계 안내형**(홈 화면 추가처럼 순서가 있는 안내): 단계마다 번호, 한 문장 설명, 그림을 둡니다. 세로로 이어 붙여 스크롤로 읽게 하고,
  넘기는 슬라이드(carousel)는 쓰지 않습니다. 그림은 실제 화면을 단순화한 일러스트나 직접 찍은 화면을 쓰고, 다른 회사 아이콘 원본을 복사하지 않습니다.

**접근성 이름 유지**: 개편해도 E2E가 찾는 역할·이름은 바꾸지 않습니다. 예: `navigation` "주요 메뉴"(행사·가볼만한 곳·지도)·"행사 분야"·"행사 상태"·"행사 정렬",
`search` "사이트 검색", `region` "핵심 정보". 2026-11-21 내비게이션 개편 때 사용자 결정으로 "주요 메뉴"의 뜻과 분야 탭 이름이 바뀌었고, "행사 보기"(목록 | 월별 일정 전환)는 시안 A로 없어졌습니다. 바꿔야 하면 test 변경을 먼저 사용자에게 묻습니다([루트 AGENTS.md의 검증 및 완료](../AGENTS.md#검증-및-완료)).

## Do's and Don'ts

AI가 만든 화면에서 반복되는 흔적을 금지 목록으로 둡니다. 근거: [superdesign](https://superdesign.dev/blog/why-ai-design-looks-generic),
[925studios](https://www.925studios.co/blog/ai-slop-design-tells)가 정리한 패턴과 2026-11-06 진단 결과(`font-black` 56곳, `rounded-2xl` 이상 61곳).

**하지 않습니다**
- 방문자가 할 일에 도움이 되지 않는 문장: 개수 세기("행사는 모두 7개예요"), 날짜 기준 상태 설명("11월 15일 기준으로 모두 끝났어요"), 이미 화면에 보이는 내용을 되풀이하는 요약. 검색엔진에 알릴 문장은 화면이 아니라 meta description에 둡니다(2026-11-15 사용자 결정)
- 굵기 800·900, 모든 제목과 라벨을 가장 굵게 쓰기
- 그라데이션 배경·글자, 은은한 광채(radial glow), CSS로 그린 장식 도형, 이모지·기호(`≋`) 장식
- 크게 둥근 카드 3열 격자, 카드 안의 카드, hover 때 떠오르는 카드
- 한 항목에 배지 3개 이상
- 원색 팔레트 class(`teal-700`, `slate-600`)와 임의 hex(`text-[#07377a]`)
- 정보 없이 첫 화면을 차지하는 히어로
- placeholder만 있고 라벨이 없는 입력창
- 같은 화면의 primary 버튼 2개, 이유 없이 색이 다른 버튼

**합니다**
- 실제 데이터의 어려운 경우로 화면을 확인합니다: 긴 제목, 이미지 없음, 세로 포스터, 장소 미정, 마감, 기간이 긴 행사
- 화면마다 정보 우선순위를 먼저 정하고, 크기·굵기·위치로 계층을 만듭니다
- 빈 상태, 로딩, 오류 상태를 함께 설계합니다

## 앱 확장 대비

React Native 앱은 아직 정하지 않았습니다(알림을 통한 재방문이 동기). 지금 화면을 만들 때 아래만 지키면 나중에 옮기기 쉽습니다.

- 토큰은 역할 이름으로 씁니다. 앱을 시작할 때 둘 중 하나를 고릅니다:
  [Uniwind](https://uniwind.dev/)(Tailwind v4 `@theme`을 RN에서 그대로 사용) 또는
  [DTCG 2025.10](https://www.w3.org/community/design-tokens/2025/10/28/design-tokens-specification-reaches-first-stable-version/) JSON + Style Dictionary v5(한 원본에서 CSS와 RN 값을 함께 생성).
  NativeWind v5는 2026-09 기준 정식 출시 전이라 후보에서 뺍니다.
- hover로만 보이는 정보, 웹 전용 효과(`backdrop-blur` 등)에 의존하지 않습니다.
- 하단 고정 행동 바, 시트, 가로 스크롤 칩, 2열 카드처럼 앱에도 그대로 있는 패턴을 씁니다.
- 컴포넌트 이름과 variant(`Button` `primary`, `EventCard`)를 웹 용어(`card-hover` 등) 없이 짓습니다.

**2단계에서 한 것**
- 공통 부품: `components/ui/button-styles.ts`(primary·secondary·ghost, md·lg), `badge.tsx`, `chip-styles.ts`(3단계에서 분야 탭·글자 링크로 바꾸며 지움).

- 배지 선택 규칙: `features/events/model/badges.ts`(`selectEventBadges`, unit test `tests/unit/event-badges.test.ts`).
- 목록 카드를 목록 행(EventRow)으로 바꿨습니다. 3단계에서 다시 2열 포스터 카드(`EventCard`)로 바꿨습니다.
- 헤더: 56px 한 줄(로고 + 검색으로 이동). 카테고리 메뉴는 목록 페이지의 가로 스크롤 칩(`features/events/components/browse/category-navigation.tsx`)으로 옮겼고,
  이름 "주요 메뉴"와 링크 순서는 유지했습니다. 그래서 상세 페이지에는 카테고리 메뉴가 없습니다(경로 링크로 주제 페이지에 갈 수 있음).
- 상세: 버튼(primary 하나), 배지, 주변 명소 카드, 공유·맨 위로 버튼만 바꿨습니다. 배치는 4단계에서 바꿉니다.
- 아직 그대로인 것: 홈 히어로(3단계), 상세 배치(4단계), 폼 배치(5단계), 관리자(6단계).

1단계에서 Tailwind 기본 `rounded-sm/md/lg`는 그대로 두었습니다. 개편 전 화면이 쓰고 있어서, 값을 바꾸면 고치지 않은 화면 모양까지 달라지기 때문입니다.

**3단계에서 고친 1단계 문제**: `globals.css`의 `p { text-wrap: pretty }`가 layer 밖에 있어 Tailwind 유틸리티보다 우선했고,
`text-wrap` 축약형이 줄바꿈 여부까지 바꿔 `truncate`·`whitespace-nowrap`이 듣지 않았습니다. `@layer base`로 옮기고 `text-wrap-style`만 씁니다.
전역 요소 스타일을 새로 넣을 때는 `@layer base` 안에 둡니다.

원색 팔레트: `globals.css`의 `@theme`에서 `--color-*: initial`로 Tailwind 기본 색을 껐습니다(2026-11-06 사용자 결정). `teal-700` 같은 class는 스타일이 생기지 않습니다.
