# RECOVERY

## 기본 원칙

검증 실패 시 광범위한 수정 전에 원인을 진단한다. 요구사항이나 검증을 약화해 통과한 것처럼 만들지 않는다. 원문·위치·운영 상태처럼 외부 데이터가 연관된 변경은 먼저 읽기 전용 스냅샷을 확보한다.

## 데이터와 배포 안전장치

- 운영 변경 전 `events`와 `event_sources` 전체 행, 전체 개수 `N`, 상태별 개수를 내보낸다.
- 데이터 보정은 대상 ID와 이전값·새값을 기록한 뒤 한 행사씩 적용하고 재조회한다.
- 잘못된 과거 `event_sources` 행을 삭제하지 않고 교정된 새 행을 추가한다.
- 좌표는 공식 주소와 검증 위치 근거가 일치한 단일 장소에만 저장하고, 기존 카카오 POI 교차 확인 이력을 보존한다.
- migration 적용 전 현재 schema와 영향 행을 확인하며 실패하면 제품 데이터 변경을 중단한다.
- Vercel 배포 전 로컬 필수 검증을 모두 통과하고, 배포 후 production 감사 전 기존 배포를 완료로 대체하지 않는다.

## 실패 루프

1. 실패 출력과 브라우저 증상을 끝까지 읽는다.
2. 구현 버그 / 잘못된 테스트 / 외부 원문 변경 / 지도 키·도메인 / 네트워크 / 데이터 충돌 / scope 충돌로 분류한다.
3. PRD.md, PLAN.md, VALIDATION.md와 비교한다.
4. 가장 작은 가역 변경 1회를 적용한다.
5. 가장 작은 관련 검증부터 재실행한다.
6. 운영 데이터 변경이면 즉시 재조회하고 이전 스냅샷과 비교한다.
7. PROGRESS.md를 업데이트한다.

## 재시도 한계

같은 blocking condition 또는 validation failure가 서로 다른 3회 시도 후에도 반복되면 자체 수정을 멈추고 사용자·제품 결정을 요청한다.

PROGRESS.md에 다음을 기록한다.

- 실패한 명령 또는 완료 기준
- 시도한 세 가지 변경
- 각각의 실패 이유
- 가장 안정적인 코드·데이터·배포 상태
- 다음으로 안전한 옵션

Codex Goal을 blocked로 표시하는 것은 같은 blocker가 최소 3개의 연속 Goal turn에서 반복되고 안전한 진전이 불가능할 때로 제한한다.

## scope 잠금

- 원문 검증, 위치 근거·좌표, 네이버 인라인 지도, 이미지 fallback, 관리자 상태 UI와 관련 테스트 밖 모듈 재작성 금지
- PRD.md에 승인된 `NEXT_PUBLIC_NAVER_MAP_CLIENT_ID`, 위치 근거 필드, 좌표 쌍 제약 외 public API·DB schema 변경 금지
- 카카오·다른 지도 SDK 동시 지원, 이미지 수집, 일반 크롤러, 전체 UI 재설계 추가 금지
- 테스트·검증 삭제 또는 skip 금지
- 검증 명령을 더 약한 명령으로 교체 금지
- 원문·지도 오류를 링크 숨김이나 빈 영역으로 침묵 처리 금지
- 좁은 문제를 광범위한 refactor로 해결 금지
- 영향 모듈과 관련 테스트 밖 변경 제한

## 방향 재확인 규칙

접근법을 바꾸기 전에 Goal 문장, PRD 비범위, 현재 마일스톤, 새 변경의 직접 기여 여부를 다시 확인한다. 네이버 지도 production 사용에 필요한 Client ID나 Web 서비스 URL이 준비되지 않았으면 다른 SDK로 임의 전환하지 않고 남은 안전한 로컬 작업을 완료한 뒤 정확한 외부 설정을 요청한다. 대표 계정이 아니면 Client ID를 설정하지 않고 주소 fallback 상태로만 배포하며, 대표 계정·계정 전체 무료 잔여량·월 100,000건·일 5,000건 한도의 요청 제한 동작을 확인하지 않은 채 production 지도를 활성화하지 않는다.

## 되돌리기 규칙

- 자신의 마지막 실패 변경만 되돌린다.
- 사용자 변경과 기존 작업트리 변경은 명시적 지시 없이 절대 되돌리지 않는다.
- 기존 카카오 키 값과 새 네이버 Client ID 값을 출력·문서화·커밋하지 않는다. 공급자 전환 중 다른 사용자 변경은 보존한다.
- 운영 상태 테스트는 검증 직후 원래 상태로 복구하고 전체 상태 개수를 재확인한다.
- migration은 적용 전 백업을 남기고, 실패 시 임의 DROP이나 데이터 삭제 대신 후속 가역 migration으로 복구한다.
