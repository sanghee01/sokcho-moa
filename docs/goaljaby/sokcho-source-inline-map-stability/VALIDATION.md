## 수동 확인 절차

1. 운영 변경 전 관리자 전체 `events`와 `event_sources`를 내보내고 상태별 개수와 관리자 전체 `A`, 실제 운영 `N`, 비운영 샘플 `D`를 기록한다. 현재 고정값은 `A=28`, `N=20`, `D=8`이다.
2. 실제 운영 `N=20`의 행사 원문을 순차적으로 열어 최종 URL, 정상 응답, 상세 화면 여부, 행사명, 날짜 또는 장소를 대조한다. 샘플 `D=8`은 관리자 전수표에 제외 사유를 남기고 상태·데이터 보존을 확인한다.
3. 무비 나잇의 `mode=view` 재현이 실패하고 `bmode=view` 상세가 행사 제목·7월 22일·7월 29일 운영정보를 보여주는지 확인한다.
4. 공식 정적 파일은 브라우저에서 행사명과 날짜를 직접 확인한다.
5. 단일 장소 행사의 공식 주소·기존 카카오 POI 교차 확인 근거·저장 좌표는 변경 없이 보존됐는지 확인한다.
6. 모든 행사 상세에서 인라인 지도·지도 로딩/fallback 박스가 없고 장소명·주소·외부 지도 링크만 표시되는지 확인한다.
7. 운영 Vercel과 관리자 감사표에서 실제 운영 원문 `N/N=20/20`, 관리자 행 보존 `A/A=28/28`, 지도 SDK 요청 0건을 감사한다.
8. 관리자 상태 하나를 공개·비공개·반려로 변경하면서 버튼·행·인접 행의 `boundingBox`를 전·중·후에 측정한 뒤 원래 상태로 복구한다.
9. 복구 후 상태별 개수와 전체 개수가 변경 전 스냅샷과 같은지 재조회한다.

## 시각 검증

- [ ] 데스크톱 viewport에서 위치 텍스트·외부 지도 링크·이미지 fallback·관리자 목록 확인
- [ ] 모바일 viewport에서 위치 텍스트·외부 지도 링크·이미지 fallback·관리자 목록과 수정 화면 확인
- [ ] 지도 미리보기·로딩/fallback 박스·빈 고정 높이 영역 없음
- [x] 관리자 저장 성공·실패 중 버튼 영역·현재 행·인접 행 변화가 1 CSS px 이하
- [ ] 텍스트 겹침·잘림·가로 넘침 없음
- [ ] 카카오·네이버 지도 SDK 네트워크 요청 0건
- [ ] 장소명·주소·외부 지도 링크·이미지의 접근 가능한 이름 확인
- [ ] production 공개 화면 브라우저 콘솔 오류 0건
- [x] 첨부 화면은 재현 증거로만 사용하고 제품에 복사·재게시하지 않음

## 완료로 보지 않는 조건

- 필수 검증 중 하나라도 실패
- 전체 행사 중 하나라도 홈·목록·로그인·soft-404 또는 다른 행사 원문으로 연결됨
- URL 형태만 확인하고 실제 행사 제목·날짜·장소 대조를 생략함
- 인라인 지도·iframe·지도 로딩/fallback 박스 또는 지도 SDK 요청이 하나라도 남음
- 주소만으로 런타임 추정 좌표를 만들거나 다중 장소에 임의 핀을 저장함
- UI 기능 테스트만 통과하고 수동·시각 검토가 끝나지 않음
- 관리자 저장 중 행이나 인접 행이 1 CSS px보다 많이 이동함
- 활성 기능 테스트·검증을 삭제 또는 skip해 통과하거나, 제거된 SDK 테스트를 미리보기·SDK 요청 0건 회귀로 대체하지 않음
- 오류를 침묵 처리하거나 빈 영역으로 숨김
- PRD.md 또는 PLAN.md 밖 scope로 변경됨
- 승인된 위치 필드·좌표 쌍 제약 외 public API 또는 DB schema가 변경됨
- 사용자 변경이나 기존 행사·출처·검수 상태가 명시적 지시 없이 되돌려짐
- 원래 증상을 재현하지 않고 편집하거나 회귀 증거를 남기지 않음
