# PLAN — 행사 작성·수정 폼 UX 개선

## 목표

속초모아 운영자가 기술 메타데이터를 직접 다루지 않고도 필수 정보와 공개 화면의 노출 결과를 이해하며 행사를 작성·수정하고, 완료 후 대시보드로 자연스럽게 돌아가게 한다.

## 참조 문서

- PRD.md (`docs/goaljaby/admin-event-form-ux/PRD.md`)
- VALIDATION.md
- RECOVERY.md
- PROGRESS.md

## 마일스톤 1: 저장 계약 단순화와 데이터 보존

- 범위: 신규 slug 자동 생성, 기존 slug 보존, 마지막 확인 시각 자동 기록, 폼에서 제거할 위치·공식 URL 메타데이터의 update payload 제외와 레거시 값 보존
- 완료 조건: 새 행사에 유효한 시스템 slug가 생성되고 수정 저장으로 slug·좌표·위치 근거·위치 확인일·`official_url`이 바뀌지 않으며, 행사·출처 확인 시각은 같은 서버 시각으로 저장됨
- 검증: 관련 helper/schema/action 단위 테스트, typecheck, 테스트 행의 저장 전후 값 비교

## 마일스톤 2: 관리자 폼 정보 구조와 필수 입력 개선

- 범위: 의미 단위 section, slug·좌표·확인일·중복 URL 입력 제거, 접근 가능한 필수 표시, URL→공개 CTA 설명, 문맥형 완료 버튼
- 완료 조건: 신규·수정 폼에서 필수/선택과 각 링크의 공개 결과를 이해할 수 있고 기술 메타데이터를 직접 입력하지 않음
- 검증: 폼 관련 단위/E2E, 필수 실패 흐름, 키보드·스크린리더 label/legend 검사, 데스크톱·모바일 시각 확인

## 마일스톤 3: 운영일정 여러 줄 계약

- 범위: 운영일정 textarea, 줄 단위 정규화, 공개 상세 줄바꿈 표현
- 완료 조건: 두 줄 이상의 운영일정을 입력·저장·재수정할 수 있고 공개 상세에서 동일한 줄 구분을 확인함
- 검증: `formatOperatingSchedule` 단위 테스트, 관리자 폼과 공개 상세 E2E, 시각 확인

## 마일스톤 4: 공개 링크 중복 제거와 완료 이동

- 범위: 공개 CTA를 행사 안내·조건부 신청·자동 공유로 정리, `관련 링크` 행 제거, JSON-LD URL 정리, 작성/수정 성공 redirect와 대시보드 메시지
- 완료 조건: CTA가 입력 계약대로 한 번씩만 나타나고 신규·수정 완료가 대시보드 성공 상태로 끝남
- 검증: 신청 URL 유무별 공개 상세 E2E, redirect·성공 메시지 E2E, 접근성 이름과 analytics 속성 회귀

## 마일스톤 5: 전체 회귀와 시각 품질 확인

- 범위: 전체 정적·단위·build·E2E 검증, 두 viewport 시각 검사, 변경 diff와 scope 감사
- 완료 조건: 모든 PRD 완료 기준이 증거와 함께 충족되고 기존 위치·URL 데이터, 공개 흐름, 사용자 파일에 회귀가 없음
- 검증: VALIDATION.md 필수 명령 전체, 데스크톱·모바일 스크린샷 또는 동등한 증거, `git diff --check`, `git status --short`
